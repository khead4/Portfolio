Project Proposal
01

The subtitle model was built for one viewer.

The uploaded document defines the interface as both a media player and a subtitle transformation system. Its core problem is that most video platforms assume one primary language at a time, even when the viewing moment is shared.

User Interface

A web-based platform for simultaneous dual-language subtitles.

Users can upload a video file or supported link, upload or generate subtitle/transcript files, and select two subtitle output languages from a flexible language list. The player renders the subtitle tracks as stacked, spaced, non-overlapping lanes.

Problem Statement

Switching languages interrupts comprehension.

Current systems usually display one subtitle language at a time. Users may need browser extensions, separate translation tools, or manual language switching, which fragments understanding and reduces immersion during shared viewing.

Proposed Solution

Two subtitle tracks stay synchronized in one player.

The platform translates subtitle cues into two selected target languages, synchronizes both tracks in real time, and uses a custom renderer instead of default browser captions.

The target audience is shared, not singular.

The concept serves multicultural households, bilingual couples and families, language learners, international students, global audiences, and educational environments such as language-learning or discussion-based classes.

  • Enables shared viewing across language barriers.
  • Improves comprehension for multiple users at the same time.
  • Reduces constant subtitle switching and separate translation work.
  • Supports language learning through parallel comparison.
  • Creates a more inclusive, collaborative, and immersive experience.

Portfolio insight: subtitles become a shared cognitive system.

Rather than optimizing for individual comprehension alone, the interface supports simultaneous interpretation, comparative understanding, and co-experienced media consumption.

Contextual Analysis Report
03

The inquiry points to a shared comprehension gap.

The contextual analysis translates the participant commitments and research goals into design findings. The recurring pattern is that current subtitle systems make multilingual viewing feel individual, even when the entertainment experience is supposed to be shared.

Finding 01

Cognitive fatigue accumulates.

Second-language viewers may understand the content, but effort rises over time when captions are not in the language that supports comfort and nuance.

Finding 02

Shared viewing becomes negotiation.

Couples, families, and multilingual groups must choose whose comprehension gets priority when only one subtitle language can appear.

Finding 03

Workarounds break immersion.

External tools, separate translation searches, and browser extensions move attention away from the movie and into platform management.

Finding 04

Output labels need memory support.

Language 1 and Language 2 are easy to confuse once users reach export actions, so the selected language summary must stay visible.

Affinity findings connect directly to design requirements.

The contextual analysis now uses a visual evidence chain instead of repeated participant photos. Each cluster summarizes what appeared across the interviews, then translates that evidence into interface decisions.

Theme 01Language fatigueUsers lose energy when they must read, translate, and watch at the same time.
Theme 02Shared compromiseGroups choose easier content instead of preferred content when subtitle support is weak.
Theme 03WorkaroundsUsers rely on browser extensions, subtitle files, rewinding, and informal translation.
Theme 04Output ambiguityGenerated videos, transcripts, and SRT files need distinct labels and clear purposes.
Theme 05Immersion lossSubtitle effort can pull attention away from acting, cinematography, and emotional scenes.

Opportunity

Make language support visible at every decision point.

The interface should keep both selected languages visible during setup, processing, playback, and export. This reduces uncertainty and helps users trust which video or subtitle file they are choosing.

Design Direction

Turn subtitle display into a configurable shared layer.

Controls for stacked layout, size, spacing, position, and display mode become part of comprehension rather than decoration. The layout itself is the shared-viewing support system.

Formative Evaluation

The formative evaluation clarifies what users might misunderstand.

The cognitive walkthrough identified where users could lose confidence in the output flow. The recommendations focus on visible labels, readiness states, language summaries, and separating playback from download actions.

A cognitive walkthrough fits the stage of the work.

The formative insight is that output actions are not interchangeable.

The walkthrough showed that Watch Now, Download Video, and Download SRT are different kinds of results, so they should not be grouped vaguely as one download step. Users need to understand what each action gives them before they click.

Language 1 and Language 2 also need persistent context. If the language summary disappears, users may forget which SRT file belongs to which language. The structural fix is to connect each scenario directly to its sketch and journey, keep readiness states visible, and keep the selected language summary near every export action.

Summative Evaluation Plan
07

The final test would measure output confidence.

The summative plan evaluates whether users can tell the difference between watching the generated movie, downloading the full movie, and downloading the correct subtitle file. The central risk is confusion between Watch Now, Download Video, Language 1 SRT, and Language 2 SRT.

Completed-result Scenario

The system has generated a dual-subtitle result.

The participant needs to review the movie and save the outputs they need: start playback in the browser, download the full completed video file, and identify which subtitle language belongs to Language 1 or Language 2 before downloading the correct SRT.

Recruitment Frame

4 to 6 users with basic website and video-player experience.

The target users include students, language learners, bilingual viewers, content creators, and people who need subtitle files for editing or sharing. Technical knowledge is not required.

The research objective is output clarity.

The usability test evaluates whether users can complete the main output tasks, tell the difference between watching the generated movie, downloading the full movie, and downloading individual subtitle files, understand Language 1 and Language 2 labels, recognize when outputs are ready, and receive enough feedback during and after processing.

This is framed as a summative evaluation plan: it describes the final usability test that would be conducted if there were time to run the study.

The session tests the interface, not the participant.

The procedure asks each participant to think aloud while completing three output tasks. The moderator observes comments, hesitations, wrong clicks, confidence, and difficulty after each task, then ends with final clarity and usability questions.

Testing Environment

Desktop or laptop, modern browser, stable prototype access.

The test can run in a classroom, study room, or remote screen-sharing session using Chrome, Edge, or Firefox. Materials include the prototype, internet connection if using the deployed version, observation log, note-taking sheet, and timer.

Post-task Questions

Confidence and confusion become the key signals.

After each task, participants answer whether they completed it, how confident they are from 1 to 5, how difficult it was from 1 to 5, and whether anything was confusing.

Moderator script keeps the test neutral.

The moderator explains that the goal is to evaluate whether the interface is clear and usable, that the interface is being tested rather than the participant, and that participants should say what they are thinking as they work. If something is confusing, they are asked to say that out loud; the moderator may not help right away because the study needs to see how the interface works on its own.

03ProcessThe system transcribes and translates with step-by-step progress and time expectations.
04ReviewThe user plays the completed movie in the browser preview/player.
05SaveThe user chooses between downloading the video or downloading the correct SRT file.
Reiterated Structure

Keep language context attached to every output.

The updated journey keeps the language summary near the video preview and SRT buttons so Language 1 and Language 2 do not become abstract labels by the time the user reaches export.

Reiterated Feedback

Separate readiness from action.

The system should show that processing is complete before enabling Watch Now, Download Video, or Download SRT. That turns the output screen into a confident decision point rather than a guessing moment.

The final journey is collaborative by design.

The reiterated path supports a shared cognitive experience: both viewers can understand the content at the same time, compare subtitle tracks, and leave with the outputs they need without switching platforms or breaking the viewing moment.
